## 3. Four-stage historical narrative layer

`src/data/dishStages.json` (generated by `scripts/build_stage_data.py`) is the single source of
truth for the historical timeline. Every one of the 94 dishes has **exactly four** stages:

| # | Title | Photo label | What the record contains |
|---|---|---|---|
| I | Origin & History | Regional context | geographical/cultural origin, earliest documented reference where one exists, historical background, regional traditions, cultural significance |
| II | Ingredients | Ingredient reference | the dish's own ingredient list, regional/seasonal produce, documented post-Columbian ingredient changes |
| III | Recipe & Making | Preparation technique | technique, processing (soaking/grinding/fermenting/kneading/stuffing), traditional cookware/heat, modern evolution |
| IV | Modern Form, Serving & Recognition | Finished dish | present-day form, variations, serving style, cultural significance, GI/commercial recognition only where documented |

Each stage carries `narrative`, `details[]`, an `evidenceNote`, `sources[]` resolved against a
9-entry bibliography, and a `confidence` label: `documented` (15 dishes),
`regional-tradition` (72), `oral-tradition` (7). Where no securely dated first written
reference exists, the record says so explicitly — no invented centuries. Dated claims that
*are* supported include the 12th-century *Manasollasa* for dosaka, the 19th-century
Bengali chhena sweet tradition, Moti Mahal / post-Partition Delhi for butter chicken, and GI
registrations for Hyderabadi Haleem (2010), Banglar Rasogolla (2017), Silao Khaja (2018) and
Chak-Hao (2020).

The evidence notes state the three documentary limits from the brief: a region photo does
not prove origin; an ingredient photo is not the whole ingredient list; a modern photo is
not an ancient one. `DishPhotoEssay.tsx` now renders these narratives, per-stage details,
evidence notes and full citations in a collapsible "four-stage historical record & sources"
panel, alongside its existing four photographic acts.

### Fetch pipeline

The claimed `npm run photos:fetch` error from the old `main` state does not apply to this
branch — the script exists. It has been hardened: stage records are unwrapped correctly,
`localPhotos.json` is merged rather than rebuilt (so imported files are never dropped),
downloads are retried, image headers/dimensions are validated, writes are atomic, licence
checks are mandatory and a `photos:verify` offline integrity check was added.

**Environment limitation:** this sandbox has no outbound `curl` access to Wikimedia hosts.
`npm run photos:plan` therefore exits with code 2 and the message "Commons API unreachable …
nothing was downloaded and the archive is unchanged" — by design, since an unverified file
must never enter the site. Commons metadata was verified through the `fetch_page` tool and
the saved originals were mirrored through `image_search`; run `photos:fetch` on a machine
with Wikimedia access to mirror the remaining remote-verified photographs.
